# mc-1.7.3-orchestrator

A small Go HTTP API that orchestrates Minecraft Beta 1.7.3 servers across your machines.

It manages hosts (machines reached over SSH, or `localhost`) and the server instances
running on them. Instances are installed and managed with
[minecraft-b1.7.3-server](https://github.com/ozzenerol/minecraft-b1.7.3-server), which sets
each server up as a systemd service with the `mcserver` management tool.

## Run

```sh
docker compose up -d   # Postgres on localhost:6000
go run .               # API on :10200, migrations run on start
```

Settings live in `config.yaml`.

## HTTP requests

The API is not documented here. The `.http` files in `http/` are the reference,
and they are kept in sync with the Go handlers by a script:

```sh
./http-sync.sh
```

It runs a Claude Code agent (`claude -p`) that reads the routes and handlers in the Go
code and updates the [kulala.nvim](https://github.com/mistweaverco/kulala.nvim) `.http` files to match:
one file per package (`internal/host` -> `http/hosts.http`), one request per route.

- `http/` is its own git repo. Your hand edits are committed as `manual edits` before
  the agent runs, and the agent's changes are committed as `sync`, so the agent
  keeps your edits and you can diff or revert any run.
- The agent can only read the project and edit files inside `http/`. It never touches Go code.
- `http/http-client.env.json` holds `{{base}}`. The script creates it once from the port in `config.yaml`.
- Files for packages that no longer exist are deleted by the script, not the agent.
- After the agent runs, `http-postman.py` builds `http/postman_collection.json` from the
  `.http` files (one folder per file, `{{base}}` as a collection variable, `@name` response ids
  saved by test scripts). Import it into Postman. It is regenerated on every run, so edit the
  `.http` files, not the collection. Run `./http-postman.py` alone to rebuild it without the agent.

Run it again whenever you add or change a route.

## Layout

- `main.go` - starts the server
- `internal/host`, `internal/instance` - handlers and services
- `internal/utils` - shared errors and HTTP helpers
- `internal/db` - code generated by sqlc from `queries/`
- `migrations/` - goose migrations
- `http/` - generated `.http` request files
